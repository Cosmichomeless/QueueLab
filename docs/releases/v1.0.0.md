# QueueLab v1.0.0

Cola de trabajos asíncronos (API REST + worker + dashboard) para estudiar cómo se construye un sistema que no pierde
trabajos. **Es un proyecto de portfolio, no un producto.**

> **No hay demo pública ni entorno alojado.** Nunca se ha desplegado en ningún sitio: el presupuesto es 0 € y no se ha
> creado ninguna cuenta ni se ha expuesto nada a Internet. «Desplegado» significa aquí *el Compose público probado de
> verdad en local* (macOS arm64, Docker Desktop). Linux, `amd64` y un certificado real **no se han probado**.

## Cómo probarlo

```bash
git clone https://github.com/Cosmichomeless/QueueLab.git && cd QueueLab
docker compose up -d --wait     # la primera vez construye las imágenes (unos minutos)
scripts/smoke.sh                # sube un CSV y comprueba el resultado
```

Dashboard en `http://127.0.0.1:3000`. Más: [`docs/architecture.md`](https://github.com/Cosmichomeless/QueueLab/blob/v1.0.0/docs/architecture.md)
(piezas, garantías y fallos) y [`docs/compose-stack.md`](https://github.com/Cosmichomeless/QueueLab/blob/v1.0.0/docs/compose-stack.md).

## Qué garantiza

- **Outbox transaccional:** trabajo y evento `JOB_QUEUED` en una sola transacción de PostgreSQL; publicación con *publisher confirms*.
- **Entrega al menos una vez, sin ejecutar dos veces el mismo intento:** reclamo con `UPDATE … WHERE status IN ('QUEUED','RETRYING')`.
- **Reintentos** (3 intentos, 5 s ×2), **DLQ**, **lease de 2 min** para trabajos abandonados y reintento manual.
- **`Idempotency-Key`**, contrapresión (503 con ≥ 1.000 pendientes) y cuota (429 sobre 60/min por IP).
- Trazas OpenTelemetry, métricas Prometheus, dashboard de Grafana y id de correlación.

**No garantiza** ejecución exactamente una vez: un worker vivo que pierde sus latidos puede ser relevado y el trabajo
ejecutarse dos veces. Detalle y escenarios de fallo: [`docs/architecture.md`](https://github.com/Cosmichomeless/QueueLab/blob/v1.0.0/docs/architecture.md).

## Métricas observadas

Apple M4 Pro, todo en la misma máquina, un worker y una API, CSV de 8,6 MiB y 150.000 filas
([resultados](https://github.com/Cosmichomeless/QueueLab/blob/v1.0.0/docs/performance/benchmark-results.md)):

| Medida | Valor |
| --- | --- |
| Worker, 1 → 8 hilos | 8,3 → 40,2 trabajos/s (**4,84×**) |
| Worker, 8 → 16 hilos | Sin mejora de capacidad; latencia p50 133 → 272 ms |
| Techo del outbox (por defecto) | ≈ 49 eventos/s |
| Memoria con el Compose público (picos bajo 60 CSV) | api 235, worker 157, rabbitmq 164, postgres 64, dashboard 43, caddy 23, redis 10 MiB; límites suman 2.432 MiB |

Con la cuota y la contrapresión **desactivadas** en el benchmark y sin medir varios workers ni varias APIs.

## Trade-offs observados

| Decisión | Beneficio | Coste observado |
| --- | --- | --- |
| Outbox | No se pierde el evento si la API cae tras el commit | Una tabla y un dispatcher; techo ≈ 49 eventos/s (con lote 200 y 100 ms, 543/s en `noop`) |
| Reclamo condicional en vez de locks distribuidos | Un duplicado no ejecuta dos veces | Los duplicados llegan al worker y se descartan allí |
| Mensaje solo con `jobId` | PostgreSQL es la única fuente de verdad | Cada consumo lee la base de datos |
| Concurrencia fija | Predecible | Subirla más allá de la saturación duplica la latencia |
| Cuota en Redis | Contadores compartidos entre APIs | Una dependencia más; si Redis cae, no se limita |
| Compose público con Caddy | HTTPS y acceso con contraseña delante de todo | Cuenta única compartida; la cuota por IP pasa a ser global tras el proxy (H4) |

Más en [`capacity.md`](https://github.com/Cosmichomeless/QueueLab/blob/v1.0.0/docs/performance/capacity.md).

## Limitaciones conocidas

- **Sin autenticación ni autorización propias** (H3): la protección es una puerta (Caddy) delante, no control de acceso en la aplicación.
- Cuota por IP que detrás de un proxy es global (H4); ficheros sin cifrar y sin cuota total (H7).
- Sin purga de `jobs` y `outbox_events`; la DLQ no caduca; copias manuales y en el mismo disco.
- Una sola instancia de PostgreSQL, RabbitMQ y Redis. Solo los trabajos `noop` y `csv-import`.
- La tabla de la lista se recorta a 390 px; los e2e de Playwright no corren en CI y solo se probaron con Chromium.
- Prometheus y Grafana sin límite de memoria; `QUEUELAB_TAG` no es persistente tras una vuelta atrás.
- Las comprobaciones de CI de `main` no están marcadas como obligatorias (ajuste manual en GitHub).
- No verificado: Linux, `amd64`, certificado real, rotación de contraseñas, carga sostenida y más de dos réplicas del worker.
